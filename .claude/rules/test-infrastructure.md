# Test infrastructure rules

- **One kernel, one base class.** `phpunit.dist.xml` names `Sylament\Tests\Fixtures\Kernel` and `tests/Pest.php` extends `Sylament\Tests\TestCase` over the whole tree; never add a second of either, because a test on its own kernel exercises a world no other test sees.
- **Area ownership is by directory.** A package's area owns `tests/Packages/<Area>/`, `tests/Fixtures/<Area>/`, `tests/Fixtures/templates/<area>/`, `tests/Fixtures/icons/<area>/`, `tests/Fixtures/config/routes/<area>.php` and `tests/Fixtures/config/packages/<area>.php`; everything else under `tests/` is shared, so two areas never edit one file.
- **Create a fixture in the lowest area that needs it** (support, schemas, forms, actions, then tables and notifications, neither above the other, then panels); a higher area uses it and never edits it, and adds its own when it needs something different.
- **Never edit the `Kernel` to register a fixture.** `config/services.php` loads `Sylament\Tests\Fixtures\` from `tests/Fixtures/` with autowire and autoconfigure, so a class dropped into an area folder is registered; fixtures stay private, since `test.service_container` reaches them.
- **Exclude a non-service from that glob** as `config/`, `templates/`, `icons/`, `assets/`, `importmap.php`, `*/Entity/` and an area's `Selectors.php` are, or the loader registers what it finds there; a trait, an interface, an abstract class or an enum needs none, since the loader and autoconfiguration already keep each out of the container, so an area never edits the shared `config/services.php` for one.
- **Configure through files, one per extension:** `config/packages/<extension>.php`, `config/packages/<env>/*.php`, `config/services.php` and `config/routes/*.php`, the layout `MicroKernelTrait` imports from the kernel's config directory; the `Kernel` keeps only the bundle list, the config directory (`getConfigDir()`), the writable paths, the kernel parameters it adjusts (`getKernelParameters()`), the component-list pass with its compile-only read (`getCompiledParameter()`) and the route order.
- **Keep the route order:** `routes/live_component.php` (live routes under `/_components`), then the panel route loader, then every other `routes/*.php`; the kernel imports them in that order rather than by name.
- **Register every bundle in every environment.** An environment exists only for a configuration value that would change what other tests observe, is named after what it varies, and keeps its files in `config/packages/<env>/`; it never changes the bundle list.
- **Leave debug on** (`APP_DEBUG` unset), so a worker recompiles its container when a fixture changes.
- **Remove every `cache/` under `var/tests/` after editing a fixture SVG, or a body inside `Kernel::build()` or a compiler pass:** debug's freshness check misses both, since ux-icons caches each icon it renders and Symfony tracks a class by its signature, so every worker keeps the old markup or container.
- **Name templates, icons and live fixtures by area:** a template is `@Fixtures/<area>/…`, an icon `<area>:<name>` from `icons/<area>/` and a live component `<Area>:<Name>`, except a panel page, whose bare `#[AsLiveComponent]` the panels bundle names from its class; one Twig namespace and one icon directory serve every area.
- **Put a shipped template's own `heroicons:*` icon in the shared `icons/heroicons/`,** and only one the suite renders, because the template names it and no area owns it.
- **A test outside `tests/Packages/` asks for the container before it `make()`s a component that needs a service** (`Notification::make()->send()`), because the boot hook covers only `tests/Packages/` and, until the kernel boots, `make()` falls back to `new`, which runs no `#[Required]` setter.
- **Leave the `logger` service to `WorkerLogger`,** which writes to the worker's `log/`: FrameworkBundle's fallback prints every error a request logs to stderr, and the tester logs each exception it rethrows.
- **Write only under `WorkerDirectory::path()`** (`var/tests/[<run>/]<TEST_TOKEN or 0>`): the kernel's cache and logs, the session files, the SQLite files under `database/`, and the `primary.storage` and `secondary.storage` disks under `storage/`, reached in config as `%sylament_tests.worker_dir%`; never `sys_get_temp_dir()`, a fixed path or a source directory, because parallel workers would share it.
- **A second concurrent run in one checkout sets its own `SYLAMENT_TEST_RUN`** (`[a-z0-9_]{1,16}`), the `<run>` in the worker directory and every pool database name, since two runs sharing either fail each other's tests; `TestDatabaseExtension` stops a process whose directory another holds.
- **Resolve what differs per run at runtime:** the connection URL reaches the container as `%env(SYLAMENT_TEST_CONNECTION_URL)%`, which `TestDatabaseExtension` publishes in every process, and the cache directory is `cache/<env>/<platform>`, because a compiled container never notices that an environment variable changed.
- **Read a component list only through `ComponentRegistry`:** `ComponentListPass` exports every class tagged `sylament.component`, fixtures left out, as `sylament_tests.components`, and the registry reads it once per process from a container the `Kernel` compiles and never boots, because Pest builds a dataset before any test exists, and a boot there would hand the first test its static instances and Symfony's error handler.
- **`TestCase::tearDown()` is the reset:** it unsets every loaded `StaticInstance`, booted or not, and removes the worker's `storage/`; never add an `afterEach` that repeats it.
- **A pin of the suite's own infrastructure** (`TestCaseTest`) may observe state through any reader, a getter or a default included, because the mechanism under test is the reset, not the reader.
- **No free helper functions.** Test files share their namespace, so two areas defining one name collide; a helper that needs the container is a `TestCase` method from a trait (a shared one in a `Concerns/` folder of `tests/Infrastructure/`, an area's own `<Area>Helpers` in its fixture folder, each with one `use` line in `TestCase`), and a pure one is a static method.
- **Keep classes out of Pest's auto-loaded folders** (`Expectations/` and `Helpers/` in `tests/`): Pest `include_once`s every file there at boot and Composer autoloads the class again, so it is declared twice.
- **Keep the client's reboot on** (Symfony's default), so requests share no memory, as in production; `TestDatabase` keeps the database's state per process, so a rebooted kernel still finds the test's rows.
- **Leave preparation to the first connection:** `TestDatabaseMiddleware` has `TestDatabase` prepare once per test (SQLite copies a template over the worker's file, a server has the pool wipe the worker's `<base>[_<run>]_suite_<TEST_TOKEN>`), so a test that never connects pays nothing; never prepare, wipe or build a schema from a test.
- **Map an entity by its folder:** `config/packages/doctrine.php` maps every `<Area>/Entity/` under its namespace, so an area edits no config; an entity's short name is its table name and stays unique across areas, since a clash fails the schema build.
- **Keep the middleware order:** `RecordingMiddleware` outermost, `TestDatabaseMiddleware` inside it, `EnableForeignKeys` innermost and on SQLite only; DoctrineBundle wraps the driver from the highest priority out, and this order keeps the preparation and every `PRAGMA` out of the recorder.
- **Read the recorder from the connection,** as `InteractsWithDatabase` does, never by class: DoctrineBundle builds one per connection from the abstract definition.
- **A test that adds a trigger or helper table on a server** registers its removal with `DatabasePool::cleanUpBeforeNextWipe()` under its connection's database, as `FailingWrite` does; a wipe empties tables and drops nothing.
- **Skip a subscriber's registration in Pest's parallel coordinator** (`Parallel::isEnabled() && !Parallel::isWorker()`), as `TestDatabaseExtension` does: the coordinator bootstraps extensions after sealing PHPUnit's event facade and runs no test, and the warning recorded there fails the run without being printed.
- **Never import `tests/Infrastructure/` from any `src/`:** the Doctrine rig (`Sylament\Tests\Infrastructure\Doctrine\`, `\PHPUnit\`) is dev-only, because the root `tests/` belongs to no package and ships in none, so a `src/` import of it fatals in every split install.
- **Infrastructure and fixtures are analysed like shipped code:** PHPStan covers `tests/` at level max except every `*Test.php` under `tests/`, `tests/Pest.php` and its `Expectations/` folder, and a fixture deliberately ill-typed for the behaviour it exercises takes an identifier-scoped `@phpstan-ignore` with its reason.
- **Run the suite as CI does:** `composer test:pest` runs it `--parallel`, so a race shows the day it is written.
