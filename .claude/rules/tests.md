# Test rules

## Where a test lives

- **Mirror each package's `src/` under `tests/Packages/`:** `packages/support/src/Colors/Color.php` → `tests/Packages/Support/Colors/ColorTest.php`, so a test is found from its class without searching and a package never shares a level with the suite's machinery; that machinery mirrors `tests/` the same way (`tests/TestCase.php` → `tests/TestCaseTest.php`).
- **One file per class or trait, however many cases it holds:** never split its cases into prefix files (`AssociationReader<Shape>Test.php`), because a test is found from its class's path; a long file groups its cases with Pest's `describe()`, one block per behaviour.
- **A trait with behaviour to pin gets its own file** at its mirrored path (forms' `Components/Concerns/HasAffixesTest.php`), even for one case; a class or trait with nothing to pin gets none, and a missing file is not a gap.
- **Drive a trait that no component of its own package composes through a component of the lowest package that does** (support's `HasWeight` through schemas' `Text`), so its one home stays at its own package's mirrored path.
- **Test an anonymous `<twig:>` component where its class would sit:** support's `templates/components/Button/index.html.twig` → its mirror's `Twig/Components/ButtonTest.php`, beside the class-backed ones in `src/Twig/Components/`, so its test is found from the tag and stays put if it gains a class.
- **A class's file holds only that class's own behaviour;** what it composes from a trait is tested in the trait's file, so each behaviour has one home.
- **A case that crosses packages goes in the file of the class the user configures for it** (a table row's delete belongs to `DeleteAction`, so to actions' `DeleteActionTest.php`); there is no flows folder, because a flow has no class to be found from.
- **Declare no namespace in a test file** outside `tests/Architecture/`; Pest names the class from its path.
- **A scan of the repository's files lives in `tests/Architecture/`,** since no class leads to it, and exists only for a rule no tool checks, keeping one case that proves it can fail.
- **Declare no function in a test file:** a run of one file loads no other test file, so a scan's helper is a static method of a class under `tests/Architecture/` and a test's helper a `TestCase` method, or a static method when it needs no container.
- **Define an expectation more than one test file uses once, in `tests/Expectations/`** (`toBeRecord()` in `Records.php`), never in a test file: Pest loads that folder in every run before any test, while a test file's `expect()->extend()` exists only in a run that loaded that file.
- **Define a dataset more than one test file uses once, in its area's `tests/Datasets/<Area>.php`** (`'trigger looks'` in `Actions.php`), for the same reason: Pest loads that folder in every run, and a dataset's name is global.

## Kinds of test

- **One base class, no `Unit/`/`Integration/` split, no marker:** every test under `tests/Packages/` boots the kernel before it runs (`tests/Pest.php`), so a component `make()`d anywhere in the test, a helper's argument or a closure dataset row included, is container-built, while a plain dataset row is built when the file loads, before any boot; call `bootKernel()` only to boot another environment (`$this::bootKernel(['environment' => 'registered_colors'])`), which replaces the hook's kernel, never to get the container.
- **Use `$this::` for `KernelTestCase` statics** inside `it()`/`test()` closures (`$this::getContainer()`), never `static::` or `self::`: Pest binds `$this` to the test case, while `static::` resolves against the closure's scope.
- **Give `toThrow()` a class, never an interface such as `Throwable`,** as its argument or its closure's parameter type: Pest reads a name `class_exists()` rejects as a message substring, so `not->toThrow(Throwable::class)` passes when the closure throws.
- **Assert a call that must not throw by what it returns** (`expect($host->validateSchema($schema))->toBeNull()`), never with `not->toThrow(SomeException::class)`, which passes when the call throws any other exception.
- **Behaviour is the default kind:** drive a component as its user does, rendering it or calling it, and assert what comes out.
- **Drive a live host through `$this->createLiveComponent()` and the testing API** (`fillForm()`, `callAction()`, `assertFormSet()`), never through UX's `TestLiveComponent` itself, because the tester answers a failed validation as a browser sees it and rethrows any other exception the host threw.
- **Render a schema component through `$this->renderSchemaComponent()`,** which places it in a schema as a page renders it, so the markup asserted is the markup a page shows; render any other view component through `$this->renderViewComponent()` and a `<twig:>` component through UX's `$this->renderTwigComponent()`, so no area grows a render path of its own, and an area helper that first builds what a component needs (`TablesHelpers::renderSummarizer()`) ends in one of them; how the markup is then asserted is in `test-renders.md`.
- **Open a page through `$this->visit()`,** a GET through its route: any answer but a success rethrows the exception behind it, so a broken page fails with its cause, not an error page's markup, and a redirect, never followed, fails naming its `Location`.
- **Read what the tester's requests left in the session on its own client** (`createLiveComponent(…, client: $client)`, then `$client->followRedirect()` after a redirect, or `$this->visit($uri, client: $client)`): `test.client` is not shared, so `visit()` without `client:` opens a session without the flash or remembered state they left, and a second tester's mount reads none either, since the tester mounts outside any request.
- **Read what a request did from a fixture service through `$this::getContainer()` after the call** (`HookLog`), never from a `LiveProp` kept for the test: the client reboots the kernel before every request after its first, so the container read after a call is the one that call ran in.
- **Read what a live host's mount recorded after the tester's first `render()` and before any call or `set()`** (`HookLog`): the tester mounts only on its first use, in the test's own kernel, and the request after its first reboots that kernel.
- **Mount a page of a non-default panel with its `panelId` in `createLiveComponent()`'s data** (`['panelId' => 'nested']`): the tester mounts outside any request, so the page names no panel of its own and answers for the default one on every live request.
- **Drive an action through `mountAction()` and the tester's raw `call()` and `set()` on a non-default panel's page that mints a URL while the action is mounted** (`EditRecord`'s Cancel link): `callAction()`, `callMountedAction()`, `fillForm()` and the `assert*` helpers read the page hydrated in the test process, where it mints the default panel's URLs.
- **Pure logic states its cases as a dataset,** and only for a dense algorithm where a table of inputs and outputs is the clearest statement (`Color::calculateContrastRatio()`).
- **Derive a list a test must keep complete** (every component that offers a trait's behaviour) from `ComponentRegistry`, by the trait's contract where Filament has one (`componentsImplementing()`), else by the trait (`componentsUsing()`), never by typing it, so a new component is covered without anyone editing the test; name an exception with its reason, never the members; derive by the trait even where a contract exists when the behaviour hangs on the contract, since a list by contract agrees with a composer that drops it.
- **Derive no list for a trait a shared base class carries without a contract:** every subclass inherits it, so nothing signals "offers it" and the list would be every component minus exceptions.
- **A database test sits in the file of the class whose behaviour it pins,** beside that class's other cases, seeds with `$this->seed()`, reads back with `$this->reload()` and `$this->statementsRun()`, counted from the last `seed()` or request, so assert a count within one request; fetches `$this->entityManager()` on every use, never across a request; every test starts on an empty database with fresh ids; the platform comes from the run's environment (`composer test:mysql`), never from the test, save a premise that compares platforms (below).
- **The platform rule.** A database test runs on SQLite, MySQL and PostgreSQL, or is skipped by premise with `->skip(<condition>, '<the platform fact>')`, and a differing expectation is written literally per platform with `match (TestPlatform::current())`, never computed by a helper that mirrors the product and would agree with it either way.
- **Compare aggregates through `DriverValues::numeric()` and fail a write on purpose with `FailingWrite::afterDeletes()` (`afterUpdates()` for an update, `afterJoinTableDeletes()` for a many-to-many's join table),** since each covers the platform differences a hand-written version misses; a premise that compares platforms takes `$this->platformEntityManager()`, the one manager whose platform the test names (SQLite in memory, or MySQL or PostgreSQL for platform reads, its connection never opening), and a case that needs a second manager beside the world's takes its SQLite one, or, when a live request must write through it, a fixture service building it over the world's connection (`Actions\SecondManager`).
