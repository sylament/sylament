# Translation

Every text a user reads is either the application's, handed to a setter as a string, a `Markup` or a Symfony `TranslatableInterface`, or the toolkit's own, a message in its package's catalogue under Filament's key.
The rules are in `.claude/rules/catalogues.md`, `php.md`, `twig.md`, `frontend.md`, `bundles.md` (no wiring for `translations/`), `manifests.md` (the catalogue requires) and `test-locales.md`; this page holds the reasoning behind them, what an application must configure, and what the two gates read.

## A setter takes a message, and its getter translates it

Every human-text setter widens Filament's `string|Htmlable|Closure` to `string|Markup|TranslatableInterface|Closure`, and a closure may return a message too.
Its getter keeps its return type and returns `$this->translateText($this->evaluate(…))`: a message becomes its string, a string or a `Markup` passes untouched, and `null` stays `null`, so every template and PHP reader still receives text.
A plain string stays a literal, as in Filament, except under `translateLabel()`, which hands a string label to the translator as a key in the default `messages` domain, Filament's `__($label)` ([has-label.md](../progress/schemas/has-label.md#a-label-is-a-string-a-markup-or-a-message-translated-in-the-getter)).
Translating in the getter is where Filament translates too, with its global `__()` replaced by an injected translator; translating at render instead would hand every reader a message object, change about 150 sites and leave `blank()` unable to judge an untranslated message.
A default the toolkit sets is a message like a user's, a closure of the shape `fn () => new TranslatableMessage('create.single.label', ['label' => …], 'sylament-actions')` (the shipped one falls back to a `label_bare` key when there is no record label), so a text composed from another getter stays lazy and is translated in the request that reads it.
A toolkit text handed to another component's setter is handed over as the message, and the receiving getter translates it.

The translator reaches a component through `HasTranslator`'s `#[Required]` setter, as the `Invoker` does ([component.md](../progress/support/component.md#a-message-is-translated-through-an-injected-translator-which-a-new-built-component-lacks)).
A component built with `new` never receives one, so it throws a `LogicException` naming its class the moment a message reaches `translateText()`, while a plain string or a `Markup` never asks for the translator.
Because every default text is a message, a hand-built component throws on any default text it renders, a prebuilt action's label or a field's placeholder among them, until `setTranslator()` runs; an identity fallback would print keys instead.

A presence test reads the getter, so `hasHint()` and the like judge the translated text; `hasTooltip()` and `hasBadge()` keep testing the stored property, as Filament does ([has-tooltip.md](../progress/support/has-tooltip.md#a-message-is-translated-by-the-getter-so-a-reader-still-gets-a-string-or-markup)).
Anonymous Twig components take strings, because their props and slots are template API, so a PHP caller passes them a getter's translated value; `ComponentAttributeBag` keeps refusing a message, because extra attributes are no text API.
An option-group label is a PHP array key, which can only be `int|string`, so a user translates it before passing it, as a Filament user does with `__()`.

### A message renders exactly as the string it becomes

A message is escaped where a plain string is escaped, sanitised where one is sanitised (a notification's title and body), and raw only where the user opted into raw HTML (`Html::content()`, `allowHtml()` options), exactly as a plain string is there; the application owns what it interpolates into a raw sink.
The toolkit never wraps a message of its own in `Markup`, because an argument carrying record data would then render raw, and a message child of a schema becomes a `Text`, never the raw `Html` a `Markup` child becomes ([schema.md](../progress/schemas/schema.md#a-message-child-is-an-escaped-text)).
A message argument is plain text, so a `Markup` that goes into one is reduced with `striptags` first, while a heading that prints the `Markup` itself still renders it raw ([table.md](../progress/tables/table.md#a-markup-that-goes-into-a-message-reads-as-its-text)).

## Where no translator sits on the source, the reader translates

Some text comes from an object that holds no translator, so its return type widens to include `TranslatableInterface` and the component or service reading it translates:

- a user enum behind support's `HasLabel` or `HasDescription` ([contracts.md](../progress/support/contracts.md#text-a-contract-answers-may-be-a-message-which-its-reader-translates)), read by forms' [`HasOptions`](../progress/forms/has-options.md#an-option-label-may-be-a-message-translated-label-by-label) and [`HasDescriptions`](../progress/forms/has-descriptions.md#only-a-described-case-reaches-the-map), and by tables' `formatState()` of a [column](../progress/tables/text-column.md#a-markup-state-skips-truncation-and-affixing-escapes-whichever-side-is-not-already-markup) and of a [summarizer](../progress/tables/summarizer.md#the-formatting-trait-is-a-copy-of-the-columns-and-the-hoist-is-owed), [`IconColumn`'s text alternative](../progress/tables/icon-column.md#the-icon-is-hidden-and-the-span-beside-it-is-the-only-name) and a [group's title](../progress/tables/grouping.md#a-value-that-cannot-name-a-group-answers-null-rather-than-failing), and an option enum that implements `TranslatableInterface` without `HasLabel`, labelled by its own `trans()` ([has-options.md](../progress/forms/has-options.md#an-enum-that-is-a-message-labels-its-own-option));
- a static getter: a page's navigation label, group and badge, and a relation manager's title, badge and badge tooltip, translated by the navigation item, the tab or the table heading that reads them ([page.md](../progress/panels/page.md#a-static-getter-returns-a-message-and-the-item-that-reads-it-translates-it), [relation-manager.md](../progress/panels/relation-manager.md#a-title-a-badge-and-a-badge-tooltip-are-static-getters-that-may-return-messages));
- a value object: a `GlobalSearchResult`'s title and details, translated by the global search component;
- a user implementation: an action's record label and title hooks, which `InteractsWithRecord::translateRecordText()` narrows to text before a message composes them.

A page's breadcrumb array is the one instance value that may be a message: the page holds a translator, but the array's type is only a docblock, so the page partial translates every crumb ([page.md](../progress/panels/page.md#a-breadcrumb-may-be-a-message-which-the-page-partial-translates)).
A resource's navigation label, group and badge are instance methods that answer a message the same way, translated by the navigation item, and an override may translate a message with the resource's own `translateText()` ([resource.md](../progress/panels/resource.md#a-resources-navigation-getters-return-messages-and-its-labels-stay-strings)).
A static property cannot hold a message, because PHP forbids `new` in a property initialiser, so a page or relation manager supplies one by overriding the static getter.
A page's instance getters (`getTitle()`, `getHeading()`, the notification-title hooks) keep returning text and translate in place, so an override returns text or translates its own message through the page's translator.
A filter `Indicator` is built through `make()` and so holds a translator of its own, which translates its label ([indicator.md](../progress/tables/indicator.md#an-indicators-label-may-be-a-message-which-the-indicator-translates-itself)).

## Text that is also identity is slugged from the translated text

Section, Tabs, Tab, Wizard and Step slug their key from the heading or label, and Filament slugs the already-translated text too, so a key, a `?tab=` URL or a persisted collapse state varies by locale, and a user who needs it stable calls `->key()` ([section.md](../progress/schemas/section.md#a-translated-heading-keys-the-component-as-in-filament)).
A navigation group is matched by key or by its translated label, and the sidebar persists a group's collapsed state in the browser under the label text, so a locale switch forgets which groups were collapsed ([navigation-group.md](../progress/panels/navigation-group.md#a-label-may-be-a-message-translated-in-its-getter)).

## Every package ships its catalogue in `translations/`, which loads with no wiring

FrameworkBundle registers `<bundle path>/translations` for every bundle, and each bundle's `getPath()` is its package root, so a catalogue dropped there loads with nothing to wire, where Filament's provider calls `->hasTranslations()`.
A package's messages live in `<domain>+intl-icu.en.yaml` and its validator messages in `validators.en.yaml`; a package with no text yet, such as infolists or widgets, ships no file, and its first key brings the catalogue with it.
English is the only locale shipped; Filament's other locales map onto the same keys, so importing them is a mechanical dump of its lang arrays.

## Keys are Filament's, under a domain per package

The domain, key and catalogue rules are in `catalogues.md`; what they rest on is that a Filament user finds each text under the matching domain and key path, so Filament's locales stay importable.
Filament's keys win over English source text as ids, which is what `symfony/validator` ships, because rewording an English id would orphan every application's translation of it; the cost is that a locale with no entry falls back only along the fallback chain, which the [application requirements](#what-an-application-must-configure) cover.
A dependent may read a lower domain, and the lower catalogue then carries the key for it: tables' `TernaryFilter` reads `sylament-forms`' `components.select.boolean.*`, so those keys ship with forms.

## Messages are ICU, in YAML catalogues

The file name, nesting, quoting and ICU shapes are rules in `catalogues.md`, and the requires a catalogue brings are in `manifests.md`.
The `+intl-icu` suffix makes the translator format a catalogue's messages as ICU MessageFormat through `ext-intl`, which is what Filament's `:label` placeholders and `trans_choice()` plurals map onto, and YAML nested as Filament's lang arrays nest them makes importing a locale a dump of those arrays.

### A count the browser updates reaches it as a map of plural forms

No catalogue and no ICU formatter reach the browser, so a controller keeps no English default and reads every string from a Stimulus value the template fills.
A count text the controller updates arrives as a JSON map from `Intl.PluralRules` category to text: the server renders `one` with `count` = 1 and `other` with `count` = 2, passing `shown` = `__COUNT__`, and the controller picks the category for the document's language and replaces the token with the number it formats ([has-actions.md](../progress/tables/has-actions.md#the-selection-banner-flattens-vendors-second-wrapper-and-renders-supports-link)).
English needs only those two categories, so a locale with more needs the map extended on the server.
Any other value the browser substitutes is a token argument the same way (`__LABEL__`, `__NAME__`, `__TAG__`).

## Validator messages keep English ids in `validators`

Symfony's validator translates a constraint's `message` in the `validators` domain under the message itself, so the toolkit's own constraint messages keep English text as the id, in a flat `validators.en.yaml` with `{{ param }}` placeholders, not ICU.
Keys there would mean overriding every constraint default; an application translates a message by mapping that id in its own `translations/validators.*`.
The toolkit's own ids are schemas' *This value cannot be changed.* (the record check), forms' constraint messages under `Validation/` and those `notRegex()` and `notIn()` hand Symfony's `Regex` and `Choice`, and tables' fallback *The value is invalid.*
A constraint that reuses one of `symfony/validator`'s own texts (`RequiredValue`'s and `ValidDate`'s, the record check's taken and blank keys) needs no entry, since Symfony's catalogue already translates it.
A message id never interpolates: a label or a limit is a constraint parameter, so the id stays one catalogue entry.
A `validationMessages()` message is translated when the field builds its constraints, and the validator then finds no id for the translated text and fills the constraint's parameters into it, so an ICU catalogue message writes them quoted (`'{{ limit }}'`) ([can-be-validated.md](../progress/forms/can-be-validated.md#validation-messages-apply-after-the-constraints-are-built)).
Developer-facing exception messages stay English and untranslated.

## `plural()` and the other English shapes stay English

The catalogues translate messages, not word forms: `plural()`, `get_record_label()`, `title(allWords:)` and every label generated from a name keep their English inflection and casing, as Laravel's `Str::plural()` does for Filament.
A translated record label therefore needs its plural set explicitly (`pluralRecordLabel()`, `$pluralRecordLabel`), or the plural is derived from the translated singular by English rules ([table.md](../progress/tables/table.md#the-header-and-the-record-labels-may-be-messages-translated-in-the-getter)).
Dates, relative times and numbers keep their English formats as well, and a bulk action's failure count is passed as digits, so locale-aware formatting stays outside the catalogues.

## A notification is translated where it is sent

A notification's title or body message is translated at `send()`, in the sending request's locale, and flashed as text, so a redirect's next page shows it as sent; its close label is translated where the toast is displayed ([notification.md](../progress/notifications/notification.md#a-title-or-body-message-is-translated-at-send-and-flashed-as-text)).
`assertNotified()` therefore compares against the translated title.

## What an application must configure

The toolkit checks none of these: each is documented here instead, and only a disabled translator with neither form nor validation on stops the container from compiling.

- **An enabled translator.** Every catalogue-shipping package requires `symfony/translation`, so FrameworkBundle enables the translator by default. With `framework.translator` off, FrameworkBundle registers its `IdentityTranslator` only while `form` or `validation` is on, and every toolkit text then renders as its key (`create.single.label`); with all three off it registers no `TranslatorInterface`, so `HasTranslator`'s `#[Required]` setter cannot be autowired and the container fails to compile. The setter stays non-nullable, because a nullable one would move the failure to every default text at runtime.
- **`fallbacks: [en]` when the default locale is not `en`.** Symfony falls back only to the default locale when `framework.translator.fallbacks` is empty, and the toolkit ships `en` alone, so an application defaulting to another locale shows raw keys for every text it has not translated unless it lists `en`.
- **`{_locale}` on the live route of a URL-locale application.** UX keeps no locale across live requests, unlike Livewire, so each runs in whatever locale the application's own logic sets; an application reading the locale from the URL prefixes its live route with `{_locale}`, or a live request runs in the default locale and rebuilds every translated key, losing a mounted action ([section.md](../progress/schemas/section.md#the-locale-of-a-live-call-is-the-requests-so-a-url-locale-application-prefixes-its-live-route), [tabs.md](../progress/schemas/tabs.md#the-locale-of-a-live-call-is-the-requests-so-a-url-locale-application-prefixes-its-live-route)).
- **The `+intl-icu` suffix on an override catalogue.** An application translating a toolkit domain names its file `<domain>+intl-icu.<locale>.yaml` (`translations/sylament-actions+intl-icu.sk.yaml`); without the suffix the translator formats the message with its plain formatter, which replaces a parameter's bare name, so `Vytvoriť {label}` renders `Vytvoriť {post}`.

## The two gates

`TranslationCatalogueTest` and `UserFacingLiteralTest` keep the convention true for every package; their planted cases prove each arm can fail.

### The catalogue gate compares the keys the code uses with the catalogues

`CatalogueScan` runs the kernel's `translation.extractor`, which is `PhpAstExtractor` (over `new TranslatableMessage(…)`, `t()` and `->trans(…)`) and the Twig extractor (over `|trans`), across each package's `src/` and `templates/`.
It reports a key the code uses and the owning catalogue lacks, a key of the package's own domain that neither the package nor any package requiring it uses, a domain the package may not name, and a catalogue of a domain the package does not own, and it refuses a catalogue named in neither shape.
`lint:translations`, run through the test kernel with `--locale en`, validates the ICU syntax of every loaded catalogue.
Symfony's Twig extractor swallows a template parse error, so such a template adds no keys here; `composer test:twig` is what catches it.
`debug:translation` cannot be the gate: in bundle mode it scans only the bundle's `templates/`, and in root mode the project's `src/`, which here is `tests/Fixtures`, so it never reads `packages/*/src`.

The extractor sees no constraint message, so the scan reads validator ids itself, from these shapes:

- in a package's `Validation/` constraints, a `…message` property or promoted-parameter default, a `…message:` argument to `parent::__construct()` and a `$this->…message = …` assignment, each a literal, a `??` fallback, or a ternary or `match` arm;
- anywhere in its `src/`, a `buildViolation()` id and a value written into a `$refusals[…]` map, which `RecordKeyGuard::constraint()` turns into violations, each a literal or a `self::`/`static::` string constant of the file.

Shipped code keeps a validator id in whichever of these shapes reads best, and a shape the scan misses is taught to the scan, never worked around in the code.
`symfony/validator`'s own English ids count as held by every package's `validators` catalogue.

### The literal gate finds user-facing text that is no message

`LiteralScan` reports, per package:

- in templates, text and text attributes (`aria-label`, `title`, `placeholder`, …), string literals in expressions that are not `|trans` keys, and `<twig:>` text props;
- in PHP, a literal handed to a text setter or returned by its closure, returned by a text getter (`get<X>`, `getDefault<X>`, or a `get…` name ending in `title`, `label`, `heading`, `description`, `placeholder`, `tooltip` or `message`), a text-named property default, a text-keyed array entry, and a literal fed to a text-building function such as `sprintf()`;
- in TypeScript, a `default:` string, a text assignment and a text-named binding.

It leaves alone what reads as a token rather than text: a `__WORD__` placeholder, one lowercase-led word with no whitespace (a Stimulus action, a placement), `sy-` class lists, array keys, comparison and `match` operands, a message's key and domain, anything under a `throw`, and a literal handed straight to a call that neither sets text nor builds it.
