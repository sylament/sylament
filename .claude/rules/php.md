# PHP rules

- **Strict types.** Open every file with `declare(strict_types=1);`; PHP-CS-Fixer's `declare_strict_types` restores it on `composer format`, so a file without it is unformatted.
- **Closures are values until evaluated.** Read a configurable `T|Closure` through `evaluate()`, which invokes only a `Closure` instance; a string naming a function (`'date'`) is returned as a value, never called.
- **Injection order.** The `Invoker` fills each closure parameter from named injections, typed injections (`self`/`parent` normalised; a `Closure` injection value is called and its result passed), the resolver, the container (only a type it `has()`), the default, then `null` when optional or nullable, else it throws naming the class; never expect auto-wiring of an unbound class, which Symfony's container cannot build.
- **Variadics** receive only an explicit named, typed or resolver injection and are otherwise skipped, so they never get the stray `null` Filament passes.
- **Inject by Filament's names.** Port Filament's injection names (`$get`, `$state`, `$record`, …) into `resolveDefaultClosureDependencyForEvaluationByName()`/`ByType()`, returning `ClosureParameter::make($value)` or deferring to `parent::`; a bare `null` return means "not mine", which is why a resolved `null` is wrapped.
- **Set `$evaluationIdentifier`** on every class Filament gives one, to Filament's value (`component`, `schema`, `action`, `table`, `column`, …); a parameter of that name, or typed as a class the object is, then receives the object.
- **Closure typing.** A setter takes a native `…|Closure` union and assigns it directly with no `@param`; never write a `callable():T` or `Closure():T` spec for a closure the `Invoker` fills, because PHPStan cannot model injected parameters and the spec rejects consumers' `fn (Section $component) => …`. `evaluate()`'s `@template T` is what types the getter.
- **Human text** is typed `string|Markup|Closure` wherever Filament types `string|Htmlable|Closure`; templates escape a string and render a `Markup` raw, which is the `Htmlable` contract.
- **Uniform traits.** When Filament puts a trait on a base class that only some subclasses use (`HasColumns` on `Component`), do the same unless you can argue the divergence; the trait is there for uniform fluent composition.
- **Grow by traits:** add a focused `Concerns/Has*` trait rather than widening an existing class, so the port maps onto Filament's traits.
- **Construction.** A component's `make()` calls `static::newInstance()` and then `configure()`, never `new static()`: `ComponentResolver` returns the container's autowired, non-shared instance and falls back to `new $class()`, so a subclass with constructor dependencies must be a registered service.
- **Services reach a component through a `#[Required]` setter,** and its getter either builds a dependency-free fallback or throws a `LogicException` saying to register the class; a `new`-built object never runs the setter.
- **Static instances** (`StaticInstance` plus `HasStaticInstance`) are only for a service that a static method or a free function must reach (`configureUsing()`, `newInstance()`); an instance method takes a `#[Required]` setter, and a new static instance also joins the Unit unset hooks in each `tests/Pest.php`, or its state leaks between tests.
- **`configureUsing()` order:** root class first, `setUp()` at the class that declares it, each class's closures after it, important closures last; `during:` scopes a registration to one call, otherwise the return value removes it.
- **Template context.** `render()` passes `component`, then `getExtraTemplateData()`, then `templateData()`, which wins; put in `getExtraTemplateData()` only what one getter cannot give (generated ids, fallback chains, cross-trait policy), since the template reads the rest as `component.x`.
- **A `LiveProp`'s same-named getter shadows it on the wire,** because UX dehydrates through the property accessor; bridge a client-written prop with `dehydrateWith:`, or rename the property and keep the wire name with `fieldName:`, never by renaming Filament's getter.
- **Trait placement.** File a trait in the `Concerns/` of the tier that composes it: `Components/Concerns/` when any component uses it, even if the root object does too; `src/Concerns/` for the root object's or a host's own; a tier directory where Filament has one (`Table/Concerns/`); never sub-group by feature, since migrating users map Filament's flat namespaces.
- **Identify a trait by its import,** never by the bare `use X;`: `HasState`, `HasKey` and several more exist in both `Concerns/` tiers with different meanings.
- **Contracts** follow the same line: one a host implements in `src/Contracts/`, one a component implements in `Components/Contracts/`, a marker neither implements beside the capability that consults it (`Validation/Contracts/`); no `Interface` suffix, because `Contracts\` says it.
- **File an engine by capability at `src/` level** (`Evaluation/Invoker`, `Configuration/ComponentManager`), never inside `Components/`: the bundle registers every top-level class there as a component, and a static instance defined twice is `setInstance()`d twice.
- **Helpers.** Port a Laravel helper into `packages/support/src/helpers.php` and a Filament-forms one into `packages/forms/src/helpers.php`, pure and with its `docs/progress/` row in the same change; a helper needing a service belongs on the class that owns that service, since a free function can only reach one globally.
- **No inlined helper bodies.** Call the port, or the Symfony mechanism `docs/principles.md` §2 maps it to (`data_get` → `State\PropertyAccessor`), never a hand-rolled copy at the call site.
- **The ports:** support has `blank`, `filled`, `wrap`, `only`, `except`, `get_record_label`, `plural`, `sanitize_url`, `sanitize_css_color`, `diff_for_humans`, and forms `array_move_before`, `array_move_after`, all imported with `use function`. `blank()` trims with `mb_trim` and reads a `Markup` as text, so whitespace-only text is blank in both.
- **An optional package fails loudly.** A feature a developer opts into behind a `suggest`ed package (`markdown()`, `currentPassword()`) throws a `LogicException` naming the package; only an ambient integration Filament itself skips (an action's notification) returns early.
- **DBAL `ParameterType`/`ArrayParameterType` are values only,** never a declared type or a positive `instanceof`: they are classes on DBAL 3 and enums on DBAL 4, and only 4 is installed, so `DbalParameterTypeDeclarationTest` is the only gate.
- **PHPStan errors are fixed at the cause** (an unguarded nullable wants a throw, as in `getSchemaComponentOrFail()`) and a genuinely unfixable one goes in a baseline file, never inline; `StaticAnalysisSuppressionTest` enforces it, and a stale ignore fails the run.
- **Comment content.** Type-carrying PHPDoc (`@param`, `@return`, `@template`, `@var`, `@phpstan-assert*`) is never optional at level max; beyond it, keep only contract prose a signature cannot carry, an invariant at its enforcement point (`// Security:`), and why a `catch` swallows, and judge a comment Filament or Laravel also carries the same way, since comment style is idiom.
- **Live panel pages.** Give every concrete panel page and relation manager a bare `#[AsLiveComponent]`; UX finds a live parent by reflecting for it, and the page passes refuse a class without it.
- **A new component directory** under `Components/` needs its level added to the bundle's service glob (`bundles.md`); the glob names levels, so an unlisted one registers nothing and `make()` falls back to `new`.
- **Identity goes through `Identity\`.** Compare, select, group, order, chunk and batch record identifiers through `IdentifierConstraint`, and mint or decode keys through `RecordKey`, never through a single id column, because a record may be keyed by several fields or by an association.
- **Decode a client-supplied key before binding it.** On a malformed key, answer "no such record" without querying (`IdentifierConstraint::equals()` returns `null`), because an untyped bind lets `05` alias record 5 and turns a non-numeric key into a 500.
- **Never construct an `AssociationReader`.** Rebind the one a site already holds with `withEntityManager()`; an application may subclass or decorate the service, and `new AssociationReader(...)` drops that in silence. `AssociationReaderConstructionTest` pins it.
