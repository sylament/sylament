# Kernel test rules

## Kinds of test

- **One base class, no `Unit/`/`Integration/` split, no marker:** every test under `tests/Packages/` boots the kernel before it runs (`tests/Pest.php`), so a component `make()`d anywhere in the test, a helper's argument or a closure dataset row included, is container-built, while a plain dataset row is built when the file loads, before any boot; call `bootKernel()` only to boot another environment (`$this::bootKernel(['environment' => 'registered_colors'])`), which replaces the hook's kernel, never to get the container.
- **Behaviour is the default kind:** drive a component as its user does, rendering it or calling it, and assert what comes out.
- **Drive a live host through `$this->createLiveComponent()` and the testing API** (`fillForm()`, `callAction()`, `assertFormSet()`), never through UX's `TestLiveComponent` itself, because the tester answers a failed validation as a browser sees it and rethrows any other exception the host threw.
- **Render a schema component through `$this->renderSchemaComponent()`,** which places it in a schema as a page renders it, so the markup asserted is the markup a page shows; render any other view component through `$this->renderViewComponent()` and a `<twig:>` component through UX's `$this->renderTwigComponent()`, so no area grows a render path of its own, and an area helper that first builds what a component needs (`TablesHelpers::renderSummarizer()`) ends in one of them; how the markup is then asserted is in `test-renders.md`.
- **Open a page through `$this->visit()`,** a GET through its route: any answer but a success rethrows the exception behind it, so a broken page fails with its cause, not an error page's markup, and a redirect, never followed, fails naming its `Location`.
- **Read what the tester's requests left in the session on its own client** (`createLiveComponent(…, client: $client)`, then `$client->followRedirect()` after a redirect, or `$this->visit($uri, client: $client)`): `test.client` is not shared, so `visit()` without `client:` opens a session without the flash or remembered state they left, and a second tester's mount reads none either, since the tester mounts outside any request.
- **Read what a request did from a fixture service through `$this::getContainer()` after the call** (`HookLog`), never from a `LiveProp` kept for the test: the client reboots the kernel before every request after its first, so the container read after a call is the one that call ran in.
- **Read what a live host's mount recorded after the tester's first `render()` and before any call or `set()`** (`HookLog`): the tester mounts only on its first use, in the test's own kernel, and the request after its first reboots that kernel.
- **Mount a page of a non-default panel with its `panelId` in `createLiveComponent()`'s data** (`['panelId' => 'nested']`): the tester mounts outside any request, so the page names no panel of its own and answers for the default one on every live request.
- **Drive the actions of a host the test process resolves differently through the tester's raw `call()` and `set()`:** a non-default panel's page whose actions mint a URL of its panel (`EditRecord`'s Cancel link, which `mountAction()` may still mount), and a host on a localised route, after `setRouteLocale()`, whose keys are slugged from translated text; `callAction()` and every helper that reads the mounted action (`callMountedAction()`, `fillForm()`, `assertActionMounted()`) resolve it on the host hydrated in the test process, in the default panel and locale.
- **A database test sits in the file of the class whose behaviour it pins,** beside that class's other cases, seeds with `$this->seed()`, reads back with `$this->reload()` and `$this->statementsRun()`, counted from the last `seed()` or request, so assert a count within one request; fetches `$this->entityManager()` on every use, never across a request; every test starts on an empty database with fresh ids; the platform comes from the run's environment (`composer test:mysql`), never from the test, save a premise that compares platforms (below).
- **Assert a `src/SecondaryEntity/` record's writes through its rows** (`$this->reload()`, or a repository from `$this->entityManagerFor()`), never through `$this->statementsRun()`: `seed()` and `reload()` go through the manager that maps the record's class, but the count reads the default connection alone, so a write through the `secondary` manager never shows in it, and an empty count there proves only that the default connection ran nothing.
- **The platform rule.** A database test runs on SQLite, MySQL and PostgreSQL, or is skipped by premise with `->skip(<condition>, '<the platform fact>')`, and a differing expectation is written literally per platform with `match (TestPlatform::current())`, never computed by a helper that mirrors the product and would agree with it either way.
- **Compare aggregates through `DriverValues::numeric()` and fail a write on purpose with `FailingWrite::afterDeletes()` (`afterUpdates()` for an update, `afterJoinTableDeletes()` for a many-to-many's join table),** since each covers the platform differences a hand-written version misses; a premise that compares platforms takes `$this->platformEntityManager()`, the one manager whose platform the test names (SQLite in memory, or MySQL or PostgreSQL for platform reads, its connection never opening), and a case that needs a second manager beside the world's takes its SQLite one, or, when a live request must write through a manager the registry never serves, a fixture service building it over the world's connection (`Actions\SecondManager`); a case whose record class another registry-served manager maps uses an entity of `src/SecondaryEntity/` and reaches its manager with `$this->entityManagerFor()`, reading `$this->statementsRun()` as the default connection's statements only, so an empty list proves nothing ran on the default connection, not that nothing ran.
