# Test infrastructure rules

- **One kernel, one base class.** `phpunit.dist.xml` names `Sylament\Tests\Fixtures\Kernel` and `tests/Pest.php` extends `Sylament\Tests\TestCase` over the whole tree; never add a second of either, because a test on its own kernel exercises a world no other test sees.
- **Area ownership is by directory.** A package's area owns `tests/Packages/<Area>/`, `tests/Fixtures/src/<Area>/`, `tests/Fixtures/templates/<area>/`, `tests/Fixtures/assets/icons/<area>/`, `tests/Fixtures/config/routes/<area>.php` and `tests/Fixtures/config/packages/<area>.php`; everything else under `tests/` is shared, so two areas never edit one file, except the `use` line each area's helpers add to `TestCase`.
- **Create a fixture in the lowest area that needs it** (support, schemas, forms, actions, then tables and notifications, neither above the other, then panels), never below the package of a class it builds on (a support trait driven through a table: tables' area), save that schemas, forms and actions, which require one another, build on each other's classes from the lowest of their areas that needs it (`CodeForm`); a higher area uses it and never edits it, and adds its own when it needs something different.
- **Keep the fixtures in a Symfony app's layout** (classes in `src/`, icons in `assets/icons/`): the kernel's project directory is `tests/Fixtures`, and Symfony's defaults resolve against it.
- **Keep a file a test uploads in `assets/uploads/`** and hand it over as a test-mode `UploadedFile` (`Forms\FileUploadFixtures::file()`): the temporary store reads it through a stream and nothing moves it, so a test never copies it first.
- **Never edit the `Kernel` to register a fixture.** `config/services.php` loads `Sylament\Tests\Fixtures\` from `tests/Fixtures/src/` with autowire and autoconfigure, so a class dropped into an area folder is registered; fixtures stay private, and `test.service_container` reaches one another service references (`HookLog`), never an unreferenced one, which the compiler removes.
- **Exclude a non-service from that glob** as the `Kernel`, `Entity/`, an area's `Selectors.php`, its plain records in `Record/` and its Doctrine extensions in `Doctrine/` are, or the loader registers what it finds there; a trait, an interface, an abstract class, an enum or a host a test builds with `new` needs none, since the loader and autoconfiguration keep the first four out of the container and the host, with no constructor arguments, registers harmlessly and is removed unused, so an area never edits the shared `config/services.php` for one.
- **Configure through files, one per extension:** `config/packages/<extension>.php`, `config/packages/<env>/*.php`, `config/services.php` and `config/routes/*.php`, the layout `MicroKernelTrait` imports from the kernel's config directory; an area's own extension settings go in `config/packages/<area>.php`, and shared defaults stay in `<extension>.php`; the `Kernel` keeps only the bundle list, the project directory (`getProjectDir()`), the writable paths, the kernel parameters it adjusts (`getKernelParameters()`), the component-list pass, the compile-only read (`getCompiledContainer()`) and the route order.
- **Keep the route order:** `routes/live_component.php` (live routes under `/_components`), then the panel route loader, then every other `routes/*.php`; the kernel imports them in that order rather than by name.
- **Register every bundle in every environment.** An environment exists only for a configuration value that would change what other tests observe, is named after what it varies, and keeps its files in `config/packages/<env>/`; it never changes the bundle list.
- **Leave debug on** (`APP_DEBUG` unset), so a run recompiles its container when a fixture changes.
- **Remove every `cache/` under `var/tests/` after editing a fixture SVG, or a body inside `Kernel::build()` or a compiler pass:** debug's freshness check misses both, since ux-icons caches each icon it renders and Symfony tracks a class by its signature, so every run keeps the old markup or container.
- **Name templates, icons and live fixtures by area:** a template is `@Fixtures/<area>/…`, an icon `<area>:<name>` from `assets/icons/<area>/` and a live component `<Area>:<Name>`, except a panel page, whose bare `#[AsLiveComponent]` the panels bundle names from its class; one Twig namespace and one icon directory serve every area.
- **Put a shipped template's own `heroicons:*` icon in the shared `assets/icons/heroicons/`,** and only one the suite renders, because the template names it and no area owns it.
- **A test outside `tests/Packages/` asks for the container before it `make()`s a component that needs a service** (`Notification::make()->send()`), because the boot hook covers only `tests/Packages/` and, until the kernel boots, `make()` falls back to `new`, which runs no `#[Required]` setter.
- **Leave the `logger` service as `config/services.php` sets it,** a `Logger` at `emergency`: FrameworkBundle's fallback prints every error a request logs to stderr, and the tester logs each exception it rethrows, so a quieter or louder level, or a file, is noise nothing reads.
- **Write only under `WorkerDirectory::path()`** (`var/tests/[<run>/]<TEST_TOKEN or 0>`): the kernel's cache, the session files, the SQLite files under `database/`, and the `primary.storage` and `secondary.storage` disks under `storage/`, reached in config as `%sylament_tests.worker_dir%`; never `sys_get_temp_dir()`, a fixed path or a source directory, because two concurrent runs would share it.
- **A second concurrent run in one checkout sets its own `SYLAMENT_TEST_RUN`** (`[a-z0-9_]{1,16}`), the `<run>` in the worker directory and every pool database name, since two runs sharing either fail each other's tests; `TestDatabaseExtension` stops a process whose directory another holds.
- **Resolve what differs per run at runtime:** the connection URL reaches the container as `%env(SYLAMENT_TEST_CONNECTION_URL)%`, which `TestDatabaseExtension` publishes in every process, and the cache directory is `cache/<env>/<platform>`, because a compiled container never notices that an environment variable changed.
- **Read a component list only through `ComponentRegistry`:** `ComponentListPass` exports every class tagged `sylament.component`, fixtures left out, as `sylament_tests.components`, and the registry reads it once per process from a container the `Kernel` compiles and never boots, because Pest builds a dataset before any test exists, and a boot there would hand the first test its static instances; only a bundle's test that it registers every component reads its package's `Components/` from disk, since the registry lists what the bundle tagged and would agree with a level its glob misses.
- **`TestCase::tearDown()` is the reset:** it unsets every loaded `StaticInstance`, booted or not, and removes the worker's `storage/`; never add an `afterEach` that repeats it.
- **A pin of the suite's own infrastructure** (`TestCaseTest`, `TestDatabaseTest`) may observe state through any reader, a getter or a default included, and drive the mechanism it pins (`TestDatabase::testStarted()`), because that mechanism, not the reader or the test's lifecycle, is under test.
- **Give a helper that needs the container a trait `TestCase` uses:** a shared one in a `Concerns/` folder of `tests/Infrastructure/`, an area's own `<Area>Helpers` in its fixture folder, each with one `use` line in `TestCase`, because test files share their namespace and two areas' functions of one name collide.
- **Keep classes out of Pest's auto-loaded folders** (`Expectations/`, `Helpers/` and `Datasets/` in `tests/`): Pest `include_once`s every file there at boot and Composer autoloads the class again, so it is declared twice.
- **Keep the client's reboot on** (Symfony's default), so requests share no memory, as in production; `TestDatabase` keeps the database's state per process, so a rebooted kernel still finds the test's rows; only a case whose premise spans requests on one kernel (a second-level cache region warmed before the action, a service reset as the next request starts) passes a `disableReboot()` client to `createLiveComponent()`, since a rebooted kernel starts on an empty region and fresh services.
- **Run the root suite in one process** (`composer test:pest`, never `--parallel`, which `TestDatabaseExtension` refuses): a run owns one worker directory and one database, so no fixture, path or database has to be shared safely between workers.
- **Never import `tests/Infrastructure/` from any `src/`:** the Doctrine rig (`Sylament\Tests\Infrastructure\Doctrine\`, `\PHPUnit\`) is dev-only, because the root `tests/` belongs to no package and ships in none, so a `src/` import of it fatals in every split install.
- **Infrastructure and fixtures are analysed like shipped code:** PHPStan covers `tests/` at level max except every `*Test.php` under `tests/`, `tests/Pest.php` and its `Expectations/` folder, and a fixture deliberately ill-typed for the behaviour it exercises takes an identifier-scoped `@phpstan-ignore` with its reason.
