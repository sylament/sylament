# Upgrading

## Composite keys (M7)

Support for [composite keys](composite-keys.md) changes a few things for applications whose entities all have a single identifier:

- **Stricter URLs.** A record key in a URL must be spelled exactly as Sylament writes it. `/admin/articles/05/edit` and `+5` now return 404; before, they opened record 5. So does `5.0` (which opened record 5 on SQLite and was a database error on PostgreSQL). On PostgreSQL, uppercase, braced or 32-hex spellings of a UUID key also return 404. On MySQL and SQLite, UUID keys stored as binary now open their record; before, no spelling did.
- **Primary keys are read-only on edit.** Editing an assigned primary key (a slug, a UUID) or an auto-incremented one is refused with *This value cannot be changed.* Before, the key was rewritten or ignored.
- **Taken keys are form errors.** Creating a record with an assigned key runs one extra `SELECT` to check the key is free, and a taken key is a form error instead of a database error.
- **Blank keys are form errors.** A shared-primary-key entity saved with its mapped key association left blank is refused with *This value should not be blank.*, where the create used to fail inside Doctrine.
- **Many-to-many relation queries use `EXISTS`.** Relation managers and attach options over a many-to-many now query with `EXISTS` instead of `IN`. Results are the same. On SQLite, a very large related table can make these queries slower; PostgreSQL and MySQL plan them as before.
- **Removed methods.** `AssociationReader::getIdentifierFieldName()` is gone.
- **Constructor errors are named.** An entity whose constructor requires arguments now fails with a `LogicException` naming the class, instead of PHP's `ArgumentCountError`.
- **Filtered rows count as taken.** The check for a key already in use looks past Doctrine SQL filters. A key held by a soft-deleted or filtered-out row is now a form error instead of a database error.

## Hardening (M7 · 9)

- **Searching a non-text column works on PostgreSQL.** A `searchable()` integer, decimal, boolean, uuid or date column now compares as text there (`LOWER(col || '') LIKE …`), where every search of the table was a database error. String columns are searched exactly as before. `jsonb`, binary and array columns still cannot be searched this way; use `searchable(query:)`.
- **A search that filtered a fetched collection is refused.** A searchable column like `blocks.heading` on a table whose query fetch-joins `blocks` under the alias `blocks` used to narrow each row's collection instead of choosing rows. It now throws a `LogicException` on the first search. Alias the join something the column does not start with, or use `searchable(query:)`. A resource's globally searchable attributes are checked the same way, on the first global search; there the only way out is to alias the join differently, since an attribute has no `searchable(query:)`.
- **`$recordRouteKeyName` is checked.** Naming an association, a name the record class does not map as a field, or one field of a several-field identifier now throws a `LogicException` on first use (the first row it keys or URL it binds), where it failed later with a database or printing error, or, for one field of several, resolved a record by that field alone and failed once two records shared its value.
- **Replicate names its refusals.** A `ReplicateAction` whose copy would carry a key another record already holds is refused with a `LogicException` naming the fix (or, with a modal, *This value is already used.*), where Doctrine raised `EntityIdentityCollisionException` or a unique violation. A single string key a `prePersist` hook leaves blank is refused by name where Doctrine raised `ORMInvalidArgumentException`.
- **Second-level cache.** The by-key bulk delete evicts the cached entities of the class it deletes from. The by-key bulk dissociate evicts the cached entities of the class it updates and the owner association's cached collections.
- **Int keys.** `IdentifierConstraint::in()`, `notIn()`, `inColumns()`, `chunk()`, `batch()`, `equals()` and `notEquals()` accept int keys.

## Extensibility (M7 · 10)

- **A `query()` table that overrides `getTableRecordKey()` is refused.** On a `query()` table every read back — finding a row, a selection, select-all, reordering, a bulk delete — decodes the key Sylament mints, so an override answering another key found nothing, and select-all with one row unticked deleted the unticked row too. Such an override now throws a `LogicException` naming both keys on the first render. Return the key `RecordKey::of()` returns, or list the rows through `records()`. A `records()` table, and a row Sylament cannot key (an array, a DTO), are unaffected.
- **A taken key is shown under every key field.** *This value is already used.* now appears under each key field of the form that is not an association — the host and the path of a key made of two strings — where it appeared under the first only. A key made only of associations, and a translation keyed by its article and a locale, show it where they did.
- **A value a form hook adds and no field maps is refused.** A `mutateFormDataBeforeCreate()`, `mutateFormDataBeforeSave()` or action `mutateDataUsing()` that adds a key no field of the form maps now throws a `LogicException`, where the value was dropped in silence: `The <owner> added [<paths>] in <hook>, but no component of its <form or schema> maps those paths, so the default write would drop them. Map each with a component — a Hidden one for a value the user should not type, with required(false) where the record would otherwise require it — or <way out>.` The owner is the resource page, the action or the select's option action; the way out is setting it on the record in `makeRecord()` or `handleRecordCreation()` (create page) or `handleRecordUpdate()` (edit page), or taking the write over with `using()` (an action) or `createOptionUsing()` / `updateOptionUsing()` (a select). Overwriting a field's value is unchanged, and a key the browser sent is never refused.
- **`Select`'s create- and edit-option actions keep their data.** A `mutateDataUsing()` on them was discarded; it now reaches the record, and a key it adds that no field maps is refused as above.
- **Records whose constructor takes arguments.** The resource create page builds its record in a new `makeRecord(array $data): object`; override it to call the constructor. With no parent resource, a closure taking `$record` while the form is mapped now receives the new record instead of `null`, as it already did under a parent. A field mapped onto a property with no setter — a `readonly` key the constructor sets — used to fail with Symfony's `NoSuchPropertyException`; it is now left alone when it already holds the value the form writes, and refused with a `LogicException` naming the field when it does not. "The same value" is strict for a bool, for two strings (`'7'` over a held `'007'` is another value) and for an entity mapped with Doctrine attributes (the same instance); a blank field matches only a held `null` or `''`; a numeric string matches its number (`'5'` over a held `5`); two arrays match element by element under the same rule; and two dates or value objects of one class match when they compare equal.
- **The automatic key checks can be switched off.** `Schema::validateRecordKey(false)` skips the taken-key and blank-key checks, leaving them to you and the database. A changed key on edit is still refused. A key field over a non-nullable property is still required by the field itself, so left blank it is still *This value should not be blank.* under the field. A key field the form maps that is not required — it declares `required(false)`, or its property is nullable — and is left blank then fails the save with the existing error naming the class, which adds: *The schema switches the key rules off with validateRecordKey(false), so a key field it maps is not refused while blank; switch them back on to have the blank field refused under it.*
- **A decorated association reader is used everywhere.** The create, edit and replicate actions, the resource create page and the editable table cell used to build a plain `AssociationReader` on their entity manager. They now rebind the `sylament_schemas.association_reader` service with `withEntityManager()`, so a subclass or decorator of it runs at every write. A decorator that delegates to another reader must override `withEntityManager()` to rebind the inner one, or it keeps reading through the old entity manager.
