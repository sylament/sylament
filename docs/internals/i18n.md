# Translation

The port has no i18n layer: no catalogues, no `trans` calls, no user-facing string carrying a message id. Every user-facing literal is English, Filament's `en` text wherever Filament has one, and each trail file records the literals it adds as hardcoded English, in a "literal, not a translation key" divergence ([file-upload.md](../progress/forms/file-upload.md#literals-not-translation-keys) is one).

## Translation is one deferred pass, not a per-component port

Every field, column and action adds user-facing literals, so translating them as each component lands would put a catalogue decision into every change. The toolkit defers i18n whole instead: one dedicated pass translates everything at once, and until it lands new literals keep arriving as English with their trail notes, so the pass can find every one with `grep -rniE "literals?, not (a )?translation keys?" docs/progress/`. Filament's translation-only surface, such as `translateLabel()`, is not ported, because there is nothing behind it to switch on ([renames.md](../progress/renames.md#renames)).

## The toolkit's own validator messages ship as one catalogue per package, all at once

Some constraint messages are the toolkit's own, and no Symfony `validators` catalogue carries them:

- schemas' *This value cannot be changed.* (`State\AssociationReader`);
- forms' constraint classes under `Validation/`: `ActiveUrl`, `Alpha`, `AlphaDash`, `AlphaNum`, `Ascii`, `DateComparison`, `Distinct`, `EndsWith`, `ExistingValue`, `MatchesField`, `MinFileSize`, `Prohibited`, `StartsWith` and `UniqueValue`, plus the messages `notRegex()` and `notIn()` hand Symfony's `Regex` and `Choice` in `Components\Concerns\CanBeValidated`;
- tables' fallback *The value is invalid.* (`Concerns\HasColumns`).

The translation pass ships one `validators` catalogue per package for all of them together rather than one `.xlf` early. `UniqueValue`'s *This value is already taken.* is a second wording of the record check's *This value is already used.*, which is `UniqueEntity`'s own text and so already translated by symfony/validator's catalogue; `RequiredValue` and `ValidDate` reuse `NotBlank`'s and `Date`'s wording for the same reason.
